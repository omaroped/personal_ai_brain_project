# Release Process

## Versioning

Use lightweight semantic versioning:

- `v0.x` for fast-moving beta releases
- `v1.0.0` once setup, docs, and core demos are stable

## Release Notes Structure

Each release note should contain:

1. Summary
2. Added
3. Changed
4. Fixed
5. Breaking changes
6. Verification notes

## Minimum Release Checklist

- changelog updated
- docs reflect current behavior
- CI passing
- smoke path documented
- known limitations called out explicitly
