# Contributing

## Principles

- keep changes scoped
- preserve local-first privacy guarantees
- avoid breaking the runtime contract
- add or update tests when behavior changes

## Setup

Use the documented bootstrap path and activate the project venv before running tests.

## Before opening a PR

1. run the relevant test subset
2. update docs if behavior or setup changed
3. note any hardware or service assumptions

## Pull Requests

- describe the problem
- describe the approach
- list verification steps
- call out any residual risks
